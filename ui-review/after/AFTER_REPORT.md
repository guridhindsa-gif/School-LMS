# School LMS — UI/UX refinement report

Base commit: `13fb4e6` on `main`. **All changes are uncommitted in the working tree**, awaiting your permission to commit and push.
Before-screenshots are in `ui-review/` (from the earlier audit); after-screenshots are in `ui-review/after/`.

## 1. Summary of what was implemented

- **Junior Learning World (Classes 1–5).** This is a separate experience, not the senior interface with rounder corners:
  - A Vidya greeting with audio.
  - A large "Today's lesson" card.
  - Four illustrated destinations: Learn, Play & Explore, My Stars and Ask Vidya.
  - Junior routes `/student/junior/learn|play|stars` and a 4-item navigation.
  - A listen button for every instruction, and optional voice navigation where the browser supports speech recognition.
  - Stars counted from real correct answers.
  - 44 px or larger targets, and no placement, revision, exam or analytics language.
- **Typography and fonts.** Fonts are self-hosted with `next/font` (Bricolage Grotesque, Figtree, Baloo 2, IBM Plex Mono, Noto Sans Devanagari, Noto Sans Gurmukhi), so there is no runtime Google Fonts request. Line height and tracking are adjusted for Indic text.
- **Illustration system.** New `src/components/art`:
  - the Vidya diya character (three moods)
  - about 15 subject illustrations
  - junior destination scenes
  - icon-based badge medals
  - stars and empty-state art

  Emoji are removed from interface chrome.
- **Real interface translation** (English, हिंदी, ਪੰਜਾਬੀ):
  - 1,226 keys in 7 dictionaries cover navigation, headings, buttons, forms, validation, tooltips, aria-labels, empty states, notices and AI error messages, across student, junior, lesson, labs, quizzes, settings and all four role apps.
  - The saved language persists across pages and visits and sets `<html lang>`.
  - A unit test enforces completeness.
- **Tutor controls.** The floating "Ask Vidya" button is gone. Vidya now lives in the header. In the lesson studio on desktop the only entry is the side panel; on tablet and mobile it's the header button. Nothing overlaps content.
- **Lesson studio:**
  - A persistent **Learn → Explore → Practise → Assess → Review** path, stored per chapter in the learner store. The chapter test marks Assess with its score.
  - Mastery is shown once.
  - Narration has speed (0.75×/1×/1.25×), captions and an accessible transcript.
  - When the AI is unavailable there is an honest state with a **syllabus-based lesson clearly labelled "not generated by AI"**, notes fall back to the official topics, and the tutor shows a translated error with Try again. There are no canned answers.
- **Senior home.** Untouched subjects collapse into one "Not started yet (n)" group, and there are no 0% rings. The badge shelf moved off the home page into a single level line. Empty states are designed, and the screen is shorter.
- **Honest role dashboards.** Teacher, parent and principal show **"School data is not connected yet"** by default. **Demo data is opt-in**, bannered and badged. The AI tools that genuinely work (lesson builder, assignment maker) stay available. `docs/BACKEND_APIS.md` documents the required APIs and the absence of authentication and role-based access.
- **Accessibility:**
  - Darkened status tokens fix the pill contrast; placeholders now use the muted colour.
  - Form errors are linked (`aria-describedby`, `aria-invalid`), announced (`role="alert"`) and focused.
  - The mobile role switcher is now a menu.
  - Phones get a search icon instead of a cramped field.
  - Settings is inside the app shell.
  - Slider hit areas are 24 px.
  - The wordmark is refined, with a lamp in the logo.

## 5. Remaining functional gaps and backend dependencies

1. **Production verification.** Run `npm install` (and commit the generated lockfile), then `npm run build`, `npm run lint` and `npm test` on a networked machine. Type and build errors that the stubs hide may surface.
2. **No authentication or role-based access.** Every route is open. Server-side identity, sessions and per-role checks in each API route are required before real student data exists (see `docs/BACKEND_APIS.md`).
3. **No school data service.** Teacher, parent and principal dashboards have nothing real to show, so they show "not connected" or opt-in demo data. Student progress and staff saves stay in the browser only, with no cross-device sync.
4. **Content language.** The interface is fully translated. **Official data** (subject, unit and exam names, syllabus topics) is English as published. The hand-authored sample lessons are English. AI lessons, notes and tutor replies follow the chosen language.
5. **Lesson illustrations** inside AI-generated scenes may still use emoji, because they come from the model's JSON. A mapping from concepts to SVG art would finish the job.
6. **Page `<title>` metadata** is English (server components cannot read the browser-saved language).
7. **Voice navigation** needs browser speech recognition (Chrome and Edge); it is hidden elsewhere. Narration voice quality depends on the device's Hindi and Punjabi voices.
8. **Settings** reuses the student shell for staff visitors.
9. **Junior labs.** Only two labs (counting and fractions) are designed for Classes 1–5.

## 6. Next three highest-value improvements

1. **Make it real and safe.** Add an identity provider plus a school data API (students, classes, attempts), with server-side role checks. Commit a lockfile and add CI that runs build, lint and test, plus Playwright end-to-end tests against `next start`.
2. **Deepen the junior world.** Add 6–8 more junior labs and games (shapes, money, time, plants, animals), and a picture-concept library so AI lessons use the SVG art system instead of emoji. Review Hindi and Punjabi narration with teachers.
3. **Make the teacher and parent loop work.** Use real class mastery from student attempts, send assignments to students, and give parents a weekly digest built from their child's real data (with consent).
